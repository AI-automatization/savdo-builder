## 🟡 Важно — по приложениям

### Admin Panel
- Тот же паттерн «молчаливый провал» (`useFetch` без чтения `error`) ещё в ~7 местах: UsersPage, ChatsPage, BroadcastPage (история рассылок), StoreDetailPage (подписки/товары), SubscriptionsPage, SubscriptionDetailModal, AdminUsersPage, DatabasePage.
- ChatsPage: сбой загрузки треда — `catch { /* noop */ }`, панель просто пустая без индикации (ни сообщений, ни «нет сообщений»).
- RBAC-ошибки (403 «permission required») долетают до UI сырой английской строкой с кодом permission, не мапятся на понятный локализованный текст — хотя бэкенд отдаёт структурированный `{code, message}`.
- Аудит-лог для DB Manager (update/delete) пишется ДО мутации — если сама мутация упадёт, в audit_log остаётся «фантомная» запись о том, чего не произошло.
- **Хорошо реализовано (для контраста):** ModerationDetailPage — INV-A02 (обязательный комментарий на reject) enforced и на клиенте, и на бэке, в одной транзакции с audit_log. DatabasePage реально пишет audit log и блокирует self-lockout. BroadcastPage имеет полноценный confirm с превью получателей, не голый `window.confirm`.

### web-seller
- Отправка сообщения в чате: текст стирается ДО ответа сервера, ошибка не показывается при сбое (`chat/page.tsx:123`).
- Отмена подписки не показывает ошибку при сбое (`subscription/page.tsx:80`).
- Варианты товара и группы опций — ни одна CRUD-операция не показывает ошибку (нет try/catch, нет `.isError` нигде в этих 2 файлах, хотя рядом в `categories/page.tsx` паттерн ошибки уже есть).
- **i18n полностью отсутствует**, при этом Settings даёт продавцу выбрать «Язык интерфейса RU/UZ» — переключатель ничего не переключает, вводит в заблуждение.
- `client.ts`: защита от рефреш-петли на OTP-эндпоинтах не матчит реальные роуты (`/auth/otp/` vs реальные `/auth/request-otp`, `/auth/verify-otp`) — по факту не работает, хоть и не критично по последствиям.

### web-buyer
- Отмена заказа не показывает ошибку при сбое (`orders/[id]/page.tsx:701`).
- Прогресс-бар «до бесплатной доставки» в корзине не связан с реальной стоимостью доставки (та считается только на чекауте, за конкретный магазин) — может обмануть ожидания покупателя.
- Нет ни одного `error.tsx`/`global-error.tsx`/`not-found.tsx`/`loading.tsx` во всём App Router.
- i18n отсутствует полностью (весь текст хардкожен на русском, `lang="ru"` жёстко).
- **Живое, подтверждено:** горизонтальный оверфлоу на КАЖДОЙ странице на мобильном (390×844) — тултип кнопки темы в шапке не учитывает край экрана, `scrollWidth=634` vs `innerWidth=390` сразу после загрузки, без единого клика. На UZ-рынке с доминирующим мобильным трафиком это касается практически всех посетителей.
- **Живое:** `/orders` и `/notifications` рендерят другую шапку/навигацию, чем остальные страницы (нет «Магазины»/«Товары»/Профиль в хедере, зато мобильный BottomNavBar виден даже на десктопе 1280px).

### TMA
- `ChatPage` (и buyer, и seller) — единственная страница без auth-гейта: бьёт в API без проверки, получает 401, показывает мусорную ошибку «Не удалось загрузить чаты» + бесполезную кнопку «Повторить», вместо аккуратного «откройте через Telegram» как на Orders/Wishlist/Checkout рядом.
- `sellerNotifications.ts`: `socket.on('connect', join)` никогда не снимается при unbind → накопление listener'ов при переходах seller↔buyer без полного логаута.
- `AddProductPage.tsx`: BackButton-обработчик регистрируется и снимается двумя РАЗНЫМИ анонимными функциями → `offClick` не срабатывает, накопление обработчиков (рядом в `EditProductPage.tsx` этот же паттерн сделан правильно).

## 🟢 Мелочи (полный список — по приложениям, коротко)

**Admin:** `as any` на `import.meta.env` в 4 местах (нет типизированного `vite-env.d.ts`).
**web-seller:** необработанный promise-reject при create/edit товара (UI всё равно показывает ошибку через React Query state, но шумно в консоли); `as unknown as` на плоские `city`/`addressLine1` заказа вместо синхронизации типа с API.
**web-buyer:** кнопка «Уведомить» на товаре без остатка — мёртвая, без tooltip; поиск в шапке путает «ничего не нашли» с сетевой ошибкой; `/chats` без авторизации всё равно дёргает seller-эндпоинт (лишний 401 в консоли); 8 мест с `as unknown as` для полей вне контрактных типов.
**TMA:** **живой React-баг, подтверждён на DOM прода** — `store.reviewCount && (...)` рендерит голое число `0` рядом с карточкой любого магазина без отзывов (классическая ловушка `&&` с числом-нулём вместо булева); каталог покупателя на проде показывает тестовый магазин «ТЕСТ - удалить» с товаром «fdgh» за 99 999 сум — гигиена тестовых данных, не код; EditProductPage не умеет редактировать multi-select характеристики категории (только AddProductPage); хардкод личного TG-хендла владельца в SubscriptionPage без единой точки конфигурации (env).
